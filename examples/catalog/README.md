# Git-каталог Proteus

Содержимое этой папки можно скопировать в корень отдельного git-репозитория.
В приложении откройте **Настройки → Каталог → Источники**, введите URL
репозитория и, при необходимости, ветку. Ссылка должна вести на репозиторий,
а не на HTML-страницу или raw JSON. Поддерживается и абсолютный путь к
локальному git-репозиторию.

Нужен системный `git`; авторизация для приватного репозитория настраивается
заранее. Клиент не запрашивает пароль в терминале. При открытии используются
сохранённые данные; сеть вызывается кнопкой обновления у страницы или у
источника, а также при добавлении источника. Ошибка загрузки сохраняет
последний корректный каталог.

При первом открытии каталога добавляются собственные источники
`https://github.com/Proteus-harness/Proteus-modules.git` и
`https://github.com/Proteus-harness/Proteus-desktop-extensions.git`.
Это обычные Git-источники: их можно обновить или убрать. Удалённый источник
не возвращается при следующем открытии или обновлении клиента.

## Репозиторий skills без индекса

Если `proteus-catalog.json` в корне нет, репозиторий читается как
репозиторий Agent Skills. Каждая папка с `SKILL.md` (до 8 уровней вложенности,
включая скрытые папки вроде `skills/.curated`) становится записью `skill`;
вложенные в неё папки входят в этот skill. Frontmatter проверяется как при
discovery агента: `name` из строчных латинских букв, цифр и дефисов совпадает
с именем папки, `description` не пустое и не длиннее 1024 символов. Категория —
путь к родительской папке, версия — git tree id папки, поэтому
обновление предлагается только при изменении файлов skill. Для списка
скачиваются только файлы `SKILL.md`, остальные файлы skill — при открытии
записи и установке. Одинаковые имена в
разных папках не устанавливаются и показываются как проблемы источника.
Название каталога берётся из URL (`owner/repo`).

Так подключаются, например, открытые каталоги, предложенные в окне
«Источники»: `anthropics/skills`, `openai/skills`, `obra/superpowers`,
`huggingface/skills`.

## Индекс

Для модулей, расширений клиента, Agent Plugins и MCP-серверов в корне нужен
`proteus-catalog.json`:

```json
{
  "format": 1,
  "title": "Мой каталог",
  "categories": [{"id": "agent", "title": "Агент"}],
  "entries": [{
    "id": "review",
    "kind": "skill",
    "title": "Ревью",
    "description": "Проверка изменений",
    "category": "agent",
    "version": "1.0.0",
    "path": "skills/review"
  }]
}
```

`id` записи уникален внутри источника. Идентификаторы записей и категорий —
строчные латинские буквы, цифры и дефис, не более 64 символов, без дефиса в
начале. `category` ссылается на объявленную категорию. Обязательны непустые
`title` и `version`; `description` можно опустить. `path` — существующая
папка внутри репозитория, без абсолютных путей, `..` и `.git`.

Неизвестные поля — ошибка. Некорректная отдельная запись пропускается с
предупреждением, остальные остаются доступны; повторяющиеся `id` исключаются.
Ошибка самого индекса, его версии или категорий отклоняет обновление целиком.

`version` сравнивается как строка: любое отличие от установленной версии
предлагает обновление, а не только возрастание SemVer. При изменении файлов
публикуйте новую версию. README необязателен: файл `README.md` в папке записи
показывается в «Подробнее» (UTF-8, не более 512 КиБ).

## Типы записей

| `kind` | Содержимое `path` | Установка |
|---|---|---|
| `process_module` | Папка реализации и обязательное описание `source` | Сборка ZIP, проверка module.json и подключение через Core |
| `client_extension` | `extension.json` и программа; id манифеста совпадает с id записи | В папку расширений клиента, применяется сразу |
| `agent_plugin` | Agent Plugins 1.0: `plugin.json`, при необходимости `skills/` и `mcp.json` | Отдельная папка пакета, её путь сразу записывается в профиль |
| `skill` | `SKILL.md` с frontmatter `name` и `description`; имя skill совпадает с id записи | Пользовательская папка skills, применяется при следующем чтении skills |
| `mcp_server` | `server.json` — объект `ConfiguredMcpServerConfig`, например `{"name":"fetch","command":"uvx","args":["mcp-server-fetch"]}` | Запись сервера сразу записывается в профиль |

MCP и Agent Plugins записываются в текущий профиль при установке, без
«Сохранить»; окончательную проверку пакета и сборки выполняет существующий
сервер, и при ошибке профиль не меняется. Если на других страницах настроек
есть несохранённые правки, сначала сохраните или сбросьте их. Установка из
ZIP на странице **Packages → Из ZIP…** требует `plugin.json` в корне архива
и сохранения профиля.

Обновление Agent Plugin сохраняет его состояние «включён/выключен» в профиле,
в том числе при смене папки версии. Новая установка без прежнего подключения
включена по умолчанию.

Перед заменой расширения клиента проверяется состав подготовленного пакета,
включая ссылки на каталоги навыков с `SKILL.md`. Неполная установка или обновление
отклоняется, прежняя версия сохраняется; команда расширения при проверке
не запускается. Это относится и к установке расширений из ZIP.

Без `source` устанавливаются готовые файлы; Python,
`uvx`, `npx` и другие команды автор записи указывает в README. Для файлов
самого MCP-сервера используйте Agent Plugin; относительный `cwd` отдельного
`server.json` не поддерживается. Конфликт имени с независимо настроенным
MCP-сервером или расширением не перезаписывает его. Вручную изменённый
MCP-сервер удаляется через страницу MCP перед повторной установкой.

## Исходники модулей и расширений

Для пакета, который нужно собрать, запись дополнительно содержит:

```json
"source": {
  "path": ".",
  "build": ["python3", "package.py", "--package", "plan-tool"],
  "artifact": "dist/plan-tool.zip",
  "requirements": ["Rust", "Git", "Python 3"]
}
```

`source.path` — папка workspace внутри того же репозитория, содержащая `path`
записи. Для наших Rust-пакетов это корень: соседние path dependencies и
Cargo.lock нужны для сборки одного выбранного пакета. При нажатии «Установить»
клиент экспортирует выбранную ревизию и выполняет `build` как argv без shell.
`artifact` — путь созданного ZIP относительно workspace. Результат проверяется
перед заменой установки; код сборки запускается только по действию пользователя,
а не при загрузке каталога. Cargo использует общий кэш и два задания.
Требования устанавливаются пользователем, зависимости скачивает сборщик.
Журнал сборки ограничен 1 МиБ и находится в кэше источника.

Если `artifact` не задан, запись предлагает **«Скачать исходники»**. После
выбора папки появляется `<id>-<commit>/source/` с исходниками выбранной
ревизии, `BUILD.md` с командой сборки и `source.json` с происхождением.
Метаданные `.git` не копируются; права executable и ссылки внутри workspace
сохраняются. Открытое предложение остаётся на своей ревизии даже после
обновления источника. Существующая папка не заменяется. Исходники не
отмечаются установленными и не меняют профиль или активный слот.

В `Proteus-modules` и `Proteus-desktop-extensions` индексы генерируются из
существующих manifests командой `python3 scripts/catalog.py --write`;
`--check` проверяет актуальность без сборки. Их текущие записи описывают
исходники и результат выбранной сборки; отдельные готовые бинарники в индексах
пока не опубликованы. Модуль хранится в отдельной папке; Core регистрирует его
после проверки сборки. Обновление сохраняет существующие параметры компонентов
и не выбирает активные slots/hooks/tools автоматически.

## Локальные данные и удаление

Источники и сведения об установках хранятся в `preferences.json` клиента.
Подключения пакетов и MCP учитываются отдельно для каждого файла профиля;
расширения клиента и пользовательские skills общие.

- Кэш (частичный клон без содержимого файлов, которые ещё не открывались):
  `$XDG_CACHE_HOME/dev.proteus.native/catalogs/` или
  `~/.cache/dev.proteus.native/catalogs/`.
- Расширения: `$XDG_CONFIG_HOME/dev.proteus.native/extensions/` или
  `~/.config/dev.proteus.native/extensions/`.
- Пакеты: `$PROTEUS_HOME/plugins/`, skills: `$PROTEUS_HOME/skills/`;
  без `PROTEUS_HOME` используется `~/.proteus/`.

«Убрать» у источника удаляет только источник из списка, не установки и
не кэш. «Удалить» у расширения или skill удаляет его управляемую папку
сразу; у MCP и пакета — сразу убирает подключение из профиля.
Файлы прежних версий Agent Plugins и распакованных ZIP остаются на диске:
их могут использовать сохранённый или другой профиль. Автоматической
очистки этих папок пока нет.

При обновлении Agent Plugin сохраняются переключатель профиля и адрес
`PLUGIN_DATA`: привязка получает стабильный `data_key`, поэтому новая папка
версии использует прежние данные. Откат на прежнюю версию сохраняет тот же
ключ; данные не копируются и не удаляются. Для пакета без `data_key` Core
по-прежнему вычисляет адрес из его канонической папки.

Импорт ZIP с именем уже подключённого пакета предлагает «Заменить» или
«Отмена» и показывает путь прежнего пакета и выбранный ZIP. Совпавшее имя не означает согласие
на замену другого источника. Подтверждённая замена сохраняет `enabled` и
`data_key`, а повторный ZIP не добавляет второе подключение. Если список
пакетов изменился во время подготовки или подтверждения, импорт нужно повторить.
До нажатия «Сохранить» замена остаётся правкой draft; отмена и сброс настроек
не удаляют прежние файлы и данные.

Установка рассчитана на локальный клиент и backend на той же машине.
Исходники процессных модулей входят в каталог. Подключение собранного
бинарника в `components.*` и выбор реализации выполняются отдельно:
автоматическое изменение состава профиля при скачивании не выполняется.
