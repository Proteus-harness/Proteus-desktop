# Синтетический Codex

`mock-app-server.py` — локальный исполняемый app-server для проверки Desktop,
без авторизации, запросов к моделям и сети. Путь задаётся переменной окружения,
отдельного поля выбора executable в настройках пока нет:

```bash
PROTEUS_CODEX_EXECUTABLE="$PWD/examples/codex/mock-app-server.py" \
  ./build/Proteus/proteus-native /path/to/test-project --agent codex
```

Он содержит длинный чат из 600 строк и вложенный чат. Новый запуск без
сохранённых вкладок создаёт отдельный пустой чат.
Чтобы сохранять новые синтетические чаты между запусками, задайте
`PROTEUS_CODEX_FIXTURE_STATE` как путь к JSON-файлу внутри каталога проверки.

Отправьте обычный текст для streaming Markdown, reasoning и вывода команды.
Специальные сообщения: `/approval`, `/question`, `/permissions`, `/slow`
(проверка остановки), `/error`, `/disconnect`. Для изоляции предпочтений Desktop задайте отдельный абсолютный
`XDG_CONFIG_HOME`: fixture не читает настоящие истории, но приложение сохраняет
выбор агента и вкладки.

Для воспроизводимой проверки гонок переключения задайте
`PROTEUS_CODEX_FIXTURE_DELAYS` как JSON: ключ — метод или `метод|threadId`,
значение — задержка ответа в секундах, ограниченная диапазоном 0–5.
Правило для конкретного чата важнее общего правила метода:

```bash
export PROTEUS_CODEX_FIXTURE_DELAYS='{"thread/resume|fixture:thread/main":2,"thread/delete":1}'
export PROTEUS_CODEX_FIXTURE_RPC_LOG="$PWD/build/verification/codex-rpc.jsonl"
```

Другие запросы обрабатываются, пока ответ задержан: быстрый переход к другому
чату может завершиться первым. Содержимое ответа фиксируется до ожидания,
поэтому задержанный `thread/list` воспроизводит и устаревший ответ после
удаления. У `turn/start` уведомления начинаются только после подтверждения
запуска хода, включая режим задержки.

Необязательный журнал содержит только `method`, `threadId`, `requestId`.
Суффикс `:response` у метода отмечает отправку ответа. Это позволяет проверить
порядок ответов и количество `model/list`, не записывая содержимое сообщений.
Без этих переменных поведение fixture остаётся обычным.

Проверки стенда: `python3 -m unittest discover -s examples/codex -p 'test_*.py'`.
