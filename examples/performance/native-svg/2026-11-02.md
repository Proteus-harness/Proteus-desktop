# Ресурсы расширений и нативных изображений: 2026-11-02

Устранены три причины лишнего удержания ресурсов Desktop: растры SVG без
явного освобождения atlas, живые PTY после выключения расширения и очереди
stdio без общего бюджета. Проверены сохранённые сцены GPUI и настоящий
Terminal; первая принятая пара показала рост PSS, а не экономию RAM.
Эта работа не доказывает отсутствие других утечек или снижение всей памяти
Proteus на установленный процент.

## Что было исправлено

| Ошибка | Последствие | Изменение и причина |
|---|---|---|
| Удаление SVG из CPU-кэша не сопровождалось `App::drop_image`; удержание только сырого `Arc<RenderImage>` не описывало время жизни сохранённой сцены GPUI | При смене источника/DPI atlas мог сохранять больше не нужные изображения; немедленное удаление на eviction могло повредить повторно используемую сцену | Общий `ui/render_image::Bitmap` для SVG и отправленных миниатюр; LRU и состояние реально нарисованного элемента владеют lease. Последний владелец планирует удаление atlas на безопасном UI-такте. Сырая ссылка на pixels не оживляет вытесненный token |
| Обычный reset расширения всегда сохранял TerminalView | Выключенное/удалённое расширение оставляло PTY shell и scrollback; поздний deferred start мог запустить уже отменённый runtime | `Stop` явно останавливает PTY и очищает терминалы, `Restart` сохраняет их. Отложенный запуск проверяет поколение runtime до подготовки подключения и перед запуском |
| Чтение stdout, очередь записи и строки stdio не имели общего предела | Медленный UI/child или большое сообщение могли бесконтрольно накапливать wire-данные | Общие byte/count admission budgets, ограниченный JSON frame, входящее backpressure без потерь; исходящее переполнение явно завершает расширение с ошибкой вместо блокировки UI или молчаливого удаления сообщения |

SVG допускается к растеризации только при paint с положительным пересечением
bounds и content mask. Создание дерева/layout само по себе не выделяет bitmap.
При этом сохранены intrinsic aspect ratio и прежняя геометрия диаграмм.
Это отдельно исправлено после проверки скриншотов: первый release-прогон
показал одинаковые цвета, но другую высоту панелей, поэтому его сравнение
ресурсов **отклонено**.

LRU имеет 64 записи и 8×1024² пикселей для SVG (до 4 МиБ ключей-источников),
64 записи и 16×1024² пикселей по всем кадрам для отправленных миниатюр.
Сохранённая/показанная сцена может удерживать lease уже вытесненного Bitmap;
сумма LRU и этих leases — мягкий бюджет, не строгий предел RAM/VRAM.
Это позволяет GPUI повторно показать кэшированный кадр без нового paint,
не ломает изображение и не создаёт цикл refresh всего окна.

Stdio-бюджеты общие для приложения, не отдельные на каждое расширение:
входящие — 64 МиБ / 128 сообщений, исходящие — 32 МиБ / 128 сообщений;
JSON frame — не более 16 МиБ плюс LF. Входящий reader резервирует полный
frame до роста строки, затем уменьшает резерв до фактического объёма;
permit живёт до конца UI handler. Исходящий permit живёт через encode,
запись и flush; admission происходит до allocation encoded JSON.
Остановка закрывает очереди и будит ожидающие readers; фатальная ошибка
передаётся отдельно от занятой data-очереди и завершает собственный child.

Незавершённая строка может занимать резерв до остановки: тайм-аут не добавлен.
Wire-лимиты не ограничивают размер разобранного Node-дерева, allocator overhead,
heap/PSS или GPU. Четыре максимальных входящих frame вместе с LF не помещаются
в 64 МиБ — это консервативное ограничение, не потеря четвёртого сообщения.

## Сравнение готового SVG runtime

Постоянный стенд: [README](README.md). 16 стадий × 2 SVG, затем clear;
1280×280 на SVG, один message_id и последовательные immutable snapshots.
Corpus SHA-256:
`694f034d1d9da78d54278133ed3f50c32bf0010f84c0ba08a26ed86eb43e25fc`.
Изолированный background-gui дисплей 1440×960; только Native и синтетический
Python renderer. Модели, Core и реальные чаты не запускаются.

Для зачётной пары используются `before-final/` и `after-final-v2/`:
все 16 callbacks и все именные samples должны быть подтверждены; между
запусками сверяются corpus, source/transport/helpers/sampler hashes,
нормализованный renderer manifest, hash capture helper, initial stage и
settle-пауза 2 с. Перед продвижением проверяются настоящие PNG: обе ожидаемые
цветовые области должны быть нарисованы. Сопоставляются viewport и bounds
обеих панелей на каждой стадии; одних callbacks или совпадения цвета мало.

Первый `before/` не используется из-за гонки подтверждения именных samples.
`after-final/` и его сравнения `rejected-geometry-comparison*.json` отклонены:
границы панелей различались на всех 16 стадиях. Их PSS нельзя выдавать за
сравнение исправленного поведения. После исправления layout debug PNG
`layout-debug/stage.png` подтвердил точное совпадение границ цветных областей
первой стадии. Финальный release затем прошёл все 16 стадий и clear;
`comparison-final.json` принял входы, процедуру и границы панелей без расхождений.

Итог первой пары: после stage-15 Native PSS вырос на 12,89 МиБ, RSS —
на 8,01 МиБ. После clear `Private_Clean` изменился с 111,94 до 123,21 МиБ,
`Private_Dirty` — с 55,41 до 58,34 МиБ. Из этой пары нельзя заявлять
экономию RAM. Повтор и разбор mappings приведены ниже.
Sampler около 100 мс; дерево включает Native и synthetic renderer,
не включает driver/watcher/compositor. После clear renderer может уже
завершиться, поэтому Native и tree приводятся раздельно. GUI-память не
смешивается с headless или со сборкой; CPU totals и startup latency по этой

доказывает очистку atlas, а удаление bitmap/atlas не обязывает allocator или
драйвер немедленно уменьшить RSS. Pixel-проверка цветных панелей не доказывает
всю SVG-геометрию. Один короткий синтетический чат не доказывает отсутствие
долгоживущих утечек или строгий memory cap.

## Повтор и раскладка PSS

Вторая принятая пара `before-repeat/` / `after-repeat/` повторяет те же
32 SVG и процедуру capture без `--stop`; после clear снят `smaps`, затем
каждый Native отдельно остановлен. `comparison-repeat.json` также принял
входы и bounds всех стадий. На именном sample после clear:

| Метрика Native | До, МиБ | После, МиБ |
|---|---:|---:|
| PSS | 176.83 | 181.53 |
| RSS | 188.29 | 193.05 |

Отдельные снимки `mappings-cleared.json` дают PSS
176.80 → 181.50 МиБ. Основные разности:
`[heap]` +2.77 МиБ и чистые страницы Native
+1.96 МиБ; основные mappings NVIDIA
практически одинаковы. Анонимная память выросла на
2.72 МиБ. Это реальная
резидентная стоимость в этом прогоне; её нельзя целиком списывать на драйвер.

Новый runtime от stage-07 до stage-15 прибавил только
0.148 МиБ PSS,
затем clear — ещё
0.012 МиБ.
По этому короткому прогону нет монотонного роста на каждой новой ревизии.
Разница heap близка к размеру двух RGBA растров 1280×280 (2,734 МиБ),
но это лишь гипотеза о временных буферах/allocator high-water: `smaps`
не отличает живые allocations от свободных chunks. Allocation profile
и длительные циклы здесь не выполнялись.

Вывод: конкретные lifecycle и queue-дефекты исправлены; обе принятые пары
показали рост PSS, примерно +12,88 и +4,70 МиБ. Экономия общей RAM или
VRAM не заявляется. Стенды сохраняются для дальнейшего профилирования.
