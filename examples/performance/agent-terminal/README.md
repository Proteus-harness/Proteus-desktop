# Терминал команды агента: скрытый ввод

Стенд использует готовый portable, настоящий Core и shell-tool. Модель и сеть
не нужны. Вместо `sudo` работает Python `getpass`: команда ждёт скрытый ввод,
показывает подтверждение и завершается. Вводите только выдуманный пароль.
Установка пакетов и административные операции не выполняются.
Изолированный профиль явно подключает policy `allow_all`; его workflow всегда
запускает только подготовленный `password.py`, независимо от текста сообщения.
По умолчанию команда работает в обычной песочнице bwrap и возвращает управление
агенту через секунду. Приглашение ввода должно оставаться живым после ответа
агента: завершение потока tool-вызова не завершает процесс команды.
`--unsandboxed` отдельно проверяет запуск вне песочницы; такая проверка не
заменяет обычный путь.

Из Desktop checkout, после сборки изменённых Core, shell-tool и Desktop:

```sh
python3 examples/performance/agent-terminal/run.py --output build/verification/terminal-demo
```

Каталог output должен быть новым. Его отдельные HOME, конфигурация, workspace
и XDG state не используют настоящие чаты и профили. Launcher создаёт окно;
отправьте любое сообщение, откройте терминал у `exec_command` и введите любой
выдуманный пароль. Вкладка должна показать `PASSWORD_ACCEPTED`, затем зелёный
`TERMINAL_DEMO_DONE`. Нажатие Enter передаётся тому же PTY.

По умолчанию загружается обычный набор расширений из portable. Для отдельного
минимального сравнения есть `--no-extensions`; такой запуск не заменяет проверку
обычного клиента. Повторите открытие с закреплённым размером области и с уже
открытым терминалом в одной области с чатом: смена вкладки должна проходить
без закрытия приложения.

Для автоматической визуальной проверки запускайте runner через отдельную
background-gui session с read-only watcher на `Agent`. Временные данные и
снимки сохраняйте под `build/verification`. `--prepare-only` создаёт fixture
без запуска процессов; `--native` задаёт другой готовый portable launcher.

После запуска окна `verify.py` проверяет настоящий HTTP → Core → shell-tool
путь без модели: раннее появление ссылки, resize, скрытый ввод, финальный вывод
и отсутствие тестового пароля в истории/файлах сессии. Скрипт находит только
Core-потомка указанного Desktop с точной конфигурацией этого fixture. Bearer
token и сгенерированный пароль не печатаются и не записываются в receipt.

```sh
python3 examples/performance/agent-terminal/verify.py \
  --output build/verification/terminal-demo --desktop-pid PID
```

Результат сохраняется в `OUTPUT/wire-receipt.json`. Это проверка реального
транспорта; открытие вкладки, клавиатуру и закрытие/повторное открытие проверяйте
также в нативном интерфейсе.

Проверки: кнопка доступна до первого завершения tool-вызова; текст пароля не
появляется на экране, в выводе инструмента или journal; закрытие вкладки не
останавливает команду, явная остановка останавливает; после завершения остаётся
последний экран. Для настоящего `sudo` агент должен изначально запустить команду
с `tty: true` и необходимым разрешением на запуск вне песочницы.
