# Исправления fixture и проверочных oracle, 7 ноября 2026

Это изменения измерительного/синтетического кода из полного статического
аудита `proteus-modules-dot` (`ed5378c`). Они не доказывают исправление
одноимённых проблем production и не пересчитывают исторические RSS/PSS/CPU.

| Находка | Исправление и проверка |
|---|---|
| RDESK01 | Mock Codex использует новый UUID для каждого live turn; persisted restart → resume → send больше не повторяет turn/item IDs. Тест запускает два настоящих процесса fixture с одним synthetic state. |
| RDESK02 | Shimmer probe требует реальный положительный layout, активное окно и реальные повторные child ticker notifications. Затем проверяет продвижение child ticks при неизменном parent render count. Reduced motion отдельно требует ноль ticks. Проверка одного равенства нулевых counters больше не может дать PASS. |
| PERF1 | Chat-spaces выдаёт monotonic identity и отвергает столкновение живых path/UUID. Create C → NEW5 → delete C → create сохраняет surviving history и subscription event; удаление исходной сессии тоже покрыто. |
| PERF2 | Native-history повторно перечисляет полный durable path→hash map после teardown. Обнаруживаются добавление, удаление и изменение blob; derived cache не является canonical storage. |
| Terminal replay cleanup | Новая process session и Linux child subreaper; `finally` делает bounded stop/reap, включая отдельную process group PTY. Timeout и sampler exception проверены настоящими синтетическими parent/child процессами. |
| Terminal replay memory | Недоступные `/proc` memory-поля живого процесса явно делают попытку неполной/ошибочной. Выход между samples остаётся пределом sampling, а не нулевым полноценным наблюдением. |
| Terminal replay CLI | `--runs <= 0` отвергается до запуска; существующий report не перезаписывается, финальная запись использует exclusive create. Добавлены fingerprints runner/lifecycle. |
| Native teardown receipts | Общий `native-stream.run.teardown` выполняет все cleanup/report steps, даже если final sampler/stop упал. Terminal/images/SVG сохраняют `status=failed` и `teardown_error`, закрывают fixture и пытаются записать receipt. Инъекции final-sample и stop ошибок покрыты. |
| Mapping identity | SVG runner сохраняет исходные `root_start_ticks`; helper сравнивает их до чтения smaps. Синтетический stale PID отвергается даже при том же executable hash. |
| NS1 | Final child message ID берётся из текущей длины transcript. Bind → один/несколько append → finish сохраняет уникальность, последний текст и правильный `base.common_prefix`. |
| NS2 | Deferred A history недоступна до binding, даже по точному заранее известному пути; finish unbound A также отвергается. Неверный запрос намеренно останавливает строгий oracle; успешный post-bind flow проверен отдельно. |
| DOC1 | В README native-stream добавлен walkthrough `--deferred-a`, bind/повторные append/finish с формулами counts и revision prefixes. Default 151/150 остаётся описанием сценария без live append. |

Python-проверки запускаются отдельно по каталогам, без Core build или GUI:

```sh
python3 -m unittest discover -s examples/codex -p 'test_*.py'
python3 -m unittest discover -s examples/performance/chat-spaces -p 'test_*.py'
python3 -m unittest discover -s examples/performance/native-history -p 'test_*.py'
python3 -m unittest discover -s examples/performance/native-terminal -p 'test_*.py'
python3 -m unittest discover -s examples/performance/native-images -p 'test_*.py'
python3 -m unittest discover -s examples/performance/native-svg -p 'test_*.py'
python3 -m unittest discover -s examples/performance/native-stream -p 'test_*.py'
python3 -m unittest discover -s examples/performance/terminal -p 'test_*.py'
```

Эти восемь suites дали 96 успешных tests. Fake interpreter/`/bin/false`
в lifecycle tests не объявляется настоящим Native GUI. Rust example
`feedback_caption` прошёл `cargo check --locked -p proteus-native --example
feedback_caption` с окружением `prepare_desktop` (готовый Zig). Его
полный и reduced режимы требуют отдельного живого background display.
Новых GUI screenshots, native animation acceptance и performance measurements
в рамках этих Python-проверок нет. Старые датированные отчёты не переписаны.
