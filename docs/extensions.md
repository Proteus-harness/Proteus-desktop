# Зависимости расширений от Core

У процессного расширения `dependencies.core` по умолчанию `true`.
Документы и панели с этим требованием работают в контексте чата Proteus
Core; при выборе Codex вместо пустой поверхности показано объяснение.
Существующие пакеты без нового поля сохраняют прежнее поведение.

Локальное расширение может работать без Core:

```json
{
  "dependencies": {"core": false},
  "required_features": ["manifest.dependencies.core.v1"]
}
```

Клиент применяет декларацию ко всем `Host` пакета: оставляет рабочую папку,
не читает Core credentials и передаёт пустой `hello.server`. `session_dir`,
Core API и проекция сессии отсутствуют. Привязка к чату Core и вложенный
renderer не расширяют эту границу. Изолированные Settings/Preview также
не получают рабочую папку или credentials. Это контракт возможностей UI,
а не sandbox исполняемого процесса.

Terminal объявляет `core: false`, поэтому обычную оболочку можно открыть
рядом с чатом Codex без запуска Core. Files и Git сохраняют требование
Core, поскольку используют его API. Открытие уже запущенного терминала
агента требует отдельного протокола подключения и не следует из этой
декларации.

Полный wire-контракт — в `Proteus-desktop-extensions/PROTOCOL.md`.
