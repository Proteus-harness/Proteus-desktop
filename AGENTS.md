# Работа С Proteus-desktop

Основной клиент Proteus на GPUI. src/ — приложение, crates/client-common —
общие правила подключения и синхронизации, crates/diff — разбор diff,
crates/tabs — модель вкладок и областей без GPUI, examples/ — примеры расширений
и каталогов. Пользовательская документация — README.md, на русском языке.
Rust toolchain задан rust-toolchain.toml.

## Границы

Клиент использует публичный HTTP/SSE app-server и DTO proteus-contracts из
закреплённой Git-ревизии Proteus-core. Не импортируйте Core или реализации
модулей в UI. Поставляемые расширения живут в Proteus-desktop-extensions и
используют тот же публичный процессный протокол, что и пользовательские.
В клиенте остаются общий рендерер и нативные примитивы; логику конкретного
расширения пишите в его пакете. Не возвращайте builtin registrations или
специальные ветки по id расширения.

Держите файлы небольшими и связными, при 500–700 строках ищите разумное
разделение. Сохраняйте текущий native workflow, клавиатуру, фокус и состояние
сессии. Черновой протокол меняется вместе со всеми producers/consumers, без
legacy aliases или dual-read. Текущий сценарий — доверенные собственные
процессы; sandbox/hardening не добавляйте без поручения владельца.

## Источники И Проверка

repositories.json закрепляет Core, модули и стандартные расширения для
поставки. scripts/sources.py использует явный PROTEUS_*_SOURCE, соседние
checkout ../Proteus-core, ../Proteus-modules, ../Proteus-desktop-extensions или
загружает закреплённые revisions в build/sources.
Cargo dependencies также закреплены commit, без обязательных соседних путей.

- `python3 scripts/test.py` проверяет workspace и реальные сообщения отдельно
  поддерживаемых расширений. Для UX-правки ещё запустите реальное окно.
- Для правки только diff/tabs запускайте `scripts/test.py -p proteus-diff --lib`
  или `-p proteus-tabs --lib`: это не готовит расширения и не собирает GPUI.
  Проверки сборочных Python-скриптов уже находятся в `scripts/test_release*.py`
  и входят в desktop release gate; используйте их вместо временных копий тестов.
- `python3 scripts/run.py WORKSPACE --config PROFILE` запускает dev-клиент с
  подготовленным набором расширений.
- `python3 scripts/portable.py --fast` пересобирает актуальную переносимую папку
  build/Proteus. После завершённой и проверенной правки создайте commit, затем
  сразу обновите portable. Полный release с архивом — только по запросу или
  при проверке упаковки.
  Для правок упаковки/расширений без изменений Core/Desktop используйте
  `--fast --reuse-binaries`; готовый ZIP расширения устанавливается без сборки
  приложения. Этот режим не подтверждает свежесть существующих бинарников.

Не удаляйте target ради проверки. Cargo check не заменяет тесты поведения;
браузерная или headless-проверка не доказывает запуск готовой desktop-поставки.
GitHub Actions запускаются вручную и по релизным тегам `v*`; обычные push и PR
не запускают проверки. Сохраняйте этот режим без отдельного запроса владельца.
Секреты и реальные сессии не публикуйте.

## Zed Как Образец

Для редактора, панелей, дерева файлов, git, вкладок, меню, клавиатуры, фокуса
и анимаций не изобретайте своё: сначала найдите, как это сделано в Zed
(~/Code/zed, github.com/zed-industries/zed), и повторите поведение, раскладку,
тексты и клавиши. Код Zed можно переносить и адаптировать к gpui-kit; в начале
такого файла укажите источник: `// Адаптировано из Zed: crates/<путь>`.
Образец — исходники Zed, а не догадки по скриншоту: найдите в ~/Code/zed
код этого места и возьмите из него идею, стиль и расположение — что где стоит,
насколько компактно, какие элементы и цвета темы, как ведёт себя. Копировать
построчно не нужно; адаптируйте под наши примитивы.
Отступление от Zed — только по просьбе владельца или когда нужного примитива
нет; тогда опишите разницу в отчёте.

## Единый Стиль

Правила вида и поведения — в DESIGN.md: текст, раскрытие, меню, вкладки,
кнопки и состояния. Перед работой над интерфейсом прочитайте его; заметил
владелец новый нюанс — допишите правило туда же сразу, вместе с исправлением.
Прежде чем писать элемент, найдите его аналог в Zed и уже готовый аналог у
нас; два разных решения одной задачи сведите в одно общее и переведите на него
остальные места. Новый примитив делайте общим, опишите в его модуле, для чего
он, и перечислите в отчёте переведённые места.

Лицензии как в Zed: в корне LICENSE-GPL и LICENSE-APACHE, у каждого крейта
поле `license` в Cargo.toml и symlink на тот же файл корня. Приложение —
GPL-3.0-or-later; crates/client-common — Apache-2.0. В Apache-крейт можно
переносить только код Apache-крейтов Zed (gpui*, collections, sum_tree, util
и т. п.), код GPL-крейтов (ui, git_ui, project_panel, editor…) — нельзя.
Проверка: `python3 scripts/check_licenses.py [КОРЕНЬ]`, её запускает
scripts/test.py для клиента и расширений.
