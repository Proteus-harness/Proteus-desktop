# Proteus Desktop

Основной клиент Proteus — нативное приложение на GPUI (`gpui-kit`). Работает
с HTTP/SSE app-server через DTO из `proteus-contracts::app_protocol`; общие
правила подключения и сессий — в `crates/client-common`.

Клиент использует GPUI Kit 0.8.1 со штатным feature `gpui-fast`
(GPUI Fast 0.1.12): ядро, платформы и компоненты выбирают один backend
через общий Kit. Сохранение неизменившихся представлений, раскладки и строк
при прокрутке работает в общем UI-слое; протокол расширений остаётся тем же.
Для диагностики сохранения кадров доступны upstream-переменные
`GPUI_VIEW_RETENTION=0` и `GPUI_SCROLL_LAYERS=0`; сравнивайте один профиль,
размер окна и оптимизированную сборку. Это не замер холодного старта.

Непрерывные углы фона, рамок и изображений задаёт общий WGPU-рендерер,
включая элементы Settings и процессных расширений. Его закреплённая локальная
правка находится в `vendor/gpui-fast-wgpu` и подключается через Cargo patch;
круги и капсулы сохраняют исходную форму. Происхождение и порядок обновления
описаны в `vendor/gpui-fast-wgpu/README.proteus.md`.

Источники разделены на четыре репозитория. Этот содержит приложение,
`crates/client-common`, разбор diff в `crates/diff` и модель вкладок и областей
в `crates/tabs`. Последние два крейта не зависят от GPUI; их рендереры остаются
в приложении. DTO берутся из закреплённого Git commit Proteus-core.
`repositories.json` задаёт revisions Core, модулей и расширений для поставки.
`scripts/sources.py` читает PROTEUS_HARNESS_SOURCE / PROTEUS_MODULES_SOURCE /
PROTEUS_EXTENSIONS_SOURCE, использует соседние checkout `../Proteus-core`,
`../Proteus-modules` и `../Proteus-desktop-extensions` или загружает закреплённые
исходники в `build/sources`. Для самостоятельного clone
достаточно этого репозитория и доступа Git к публичным зависимостям.

```bash
python3 scripts/test.py
python3 scripts/run.py /path/to/project --config PROFILE
python3 scripts/portable.py --fast
python3 scripts/portable.py --fast --reuse-binaries # обновить поставку без компиляции
./build/Proteus/proteus-native /path/to/project
```

`python3 scripts/test.py` проверяет весь workspace и заранее готовит расширения.
Для отдельной проверки моделей без сборки GPUI:

```bash
python3 scripts/test.py -p proteus-diff --lib
python3 scripts/test.py -p proteus-tabs --lib
python3 -m unittest discover -s scripts -p 'test_release*.py'
```

Явный выбор только `proteus-diff`/`proteus-tabs` не загружает и не собирает
расширения. Без селектора, при смешанном выборе или неизвестных опциях
runner сохраняет полный gate с подготовкой расширений. Проверки Python
охватывают выбор scope и упаковку; они также входят в desktop release gate.

Обычный `cargo test` включает приложение и оба крейта через `default-members`.
Явный `cargo test -p proteus-native` не включает перенесённые 8 тестов diff и
38 тестов tabs; полный runner сохраняет их охват через `--workspace`.

Для сборки и упаковки расширений нужен Python 3 без дополнительных pip-пакетов. Их автор —
Proteus Project. DCP отложен в `Proteus-modules/research/dcp` и исключён из
штатных профилей, сборки и поставки. Для поставляемых JS hook adapters нужен
системный Node.js 22.18+; npm для упаковки portable не требуется.

Обычная сборка portable получает Core, Desktop и 18 самостоятельных
backend-модулей из соответствующих Cargo artifacts; настройки Cargo и кэши
наследуются. Упаковка модулей и расширений запускается из их собственных checkout.

`--reuse-binaries` упаковывает готовые файлы без Cargo и проверки их свежести.
Core и Desktop берутся из `<target>/<profile>/<binary>`, где `<target>` —
`CARGO_TARGET_DIR` либо `target`; относительный путь считается от корня каждого
checkout. По умолчанию оба профиля — `release`; при `--fast` клиент берётся из
`fast`, Core — из `release`; при `--debug` оба берутся из `debug`.
Пути backend-модулей читаются из `Proteus-modules/dist/.artifacts/release.json`
(при `--debug` — `dev.json`), сохранённого успешной сборкой `package.py`.
Расширения берутся из `<target>/release` относительно checkout расширений.
Для произвольного target triple или пути из Cargo config используйте обычную
сборку. `--reuse-hosts` сохраняет только Core/Desktop, а пакеты пересобирает.

Для правки одного расширения используйте в его репозитории
`python3 package.py --package <id>` и установите ZIP через менеджер расширений.
Core и Desktop для этого пересобирать не нужно. В репозитории Modules команда
`python3 package.py --package <id> --install /path/to/Proteus`
обновляет один пакет в готовом portable без сборки Core, Desktop и остальных.
Перезапустите backend после обновления. Общее изменение SDK/runtime может
требовать пересборки потребителей. Aggregate fixture в поставку не включается.

Эти изменения сборки адаптированы из `Qweasd123tg/proteus-modules-dot`,
ревизия `ea7409b30edec9a84a842a36d6ec56d0fbdd3059`, каталог `build-speed`.
В `share/modules/claude-command-hooks` и `share/modules/hook-process` поставляются
адаптер командных hooks и общий JavaScript SDK. Адаптер подключается явно;
упаковка не включает выполнение сторонних hooks. `bin/proteus-hook-worker`
запускает произвольный hook entry через общий контракт, а
`bin/proteus-claude-hooks-inspect` проверяет стороннюю конфигурацию без её исполнения.
История приложения и общих правил клиента сохранена из
Proteus-agent (ныне Proteus-core).

Workspace приложения отделён от Core и собирается на Rust 1.95
(`rust-toolchain.toml`). Для линковки на Linux нужны dev-пакеты xcb,
xkbcommon (с x11), fontconfig и freetype; в Fedora:

```bash
sudo dnf install libxcb-devel libxkbcommon-devel libxkbcommon-x11-devel \
  fontconfig-devel freetype-devel
```

В debug-сборке зависимости (GPUI, shaping,
tree-sitter) оптимизируются (`opt-level = 2`), сам клиент — нет, чтобы
окно не тормозило, а пересборка оставалась быстрой. Dev/test сохраняют line
tables для backtraces без тяжёлой debug-информации переменных, как Core и
Modules; для её получения задайте `CARGO_PROFILE_DEV_DEBUG=2` и
`CARGO_PROFILE_TEST_DEBUG=2`:

```bash
cargo build --release
./target/release/proteus-native [workspace] [--config <profile|path>]
./target/release/proteus-native [workspace] --origin <url> --token <token>
```

Без `--origin` клиент сам запускает `proteus server http` для workspace
(по умолчанию — текущий каталог). Бинарь сервера берётся из `PROTEUS_BIN`,
затем рядом с клиентом, затем из `PATH`; без `--config` сервер загружает
основной `config.toml`. Сервер получает `PR_SET_PDEATHSIG` и
завершается вместе с клиентом. Если сервер не поднялся или упал позже,
окно показывает его код выхода и последние строки stderr с кнопкой
«Перезапустить»; повторное открытие той же папки тоже запускает его
заново. Поток событий после ошибки переподключается с паузой от 2 до 30 с
и показывает ответ сервера, а не только факт обрыва.

При запуске сохранённая раскладка восстанавливается целиком, но Core заранее
открывает только чаты видимых панелей и текущую сессию для команд расширений.
Подготовка сервера начинается параллельно с инициализацией графики. Сохранённые
видимые чаты открываются напрямую; общий каталог сессий обновляется в фоне и
не является условием появления чата. Удалённые скрытые вкладки убираются после
получения каталога. Если сохранённой вкладки и подсказки `/bootstrap` нет,
первый выбор сессии использует каталог.
Остальные вкладки восстанавливают runtime при первом открытии и не задерживают
рабочее пространство. Модель, effort и права сначала читаются из быстрого
`/config/local`; удалённый каталог через `/config` дополняет варианты отдельно.
Ответ старого запроса не заменяет настройки, которые пользователь уже изменил.
История и сводки сессий сохраняются как готовые проекции: при открытии они
показываются сразу. Если исходный журнал изменён другим клиентом, Core обновляет
содержимое в фоне и присылает замену истории или уведомление об обновлении списка.
Перед продолжением разговора Core проверяет актуальную историю и право записи.
Первый снимок сохранённого чата содержит последние 50 завершённых строк.
При приближении к краю предыдущая или следующая страница подгружается заранее,
с сохранением позиции видимой строки. Окно просмотра удерживает до 200 строк
и около 8 MiB данных сообщений; целая страница и видимые строки сохраняются
даже при превышении бюджета. Дальние страницы выгружаются и читаются повторно
при обратной прокрутке. Подтверждённая сервером часть окна переживает reconnect
и добавление ответа. Текущий хвост с live-событиями хранится отдельно; отправка
и кнопка вниз возвращают к последним сообщениям. После завершения хода Core
освобождает полную декодированную историю, сохраняя право записи в журнал.
Текущий выполняющийся ход и первичное построение индекса пока могут читать
полную историю; их пиковая память не ограничена размером страницы.
Полный `/history` по-прежнему доступен API-клиентам.
Правый ползунок показывает положение во всей истории, включая незагруженные
страницы. Оценка общей высоты фиксируется при первом показе и не пересчитывается
при подгрузке или вытеснении страниц; читаемая строка сохраняет положение.
Перетаскивание к далёкому месту загружает одну страницу вокруг выбранного
сообщения, нижний край возвращает к живому хвосту. Пока идёт запрос, более новая
позиция указателя заменяет прежнюю.
Первый session snapshot запускает загрузку контекстного индикатора. Повторные
обновления объединяются в один активный запрос и один ожидающий; старые HTTP
ответы не заменяют более свежую telemetry из потока событий.

Для измерения запуска задайте `PROTEUS_STARTUP_TRACE=1`: stderr содержит
JSON-строки `PROTEUS_STARTUP` с временем инициализации графики/компонентов,
подготовки workspace, HTTP-операций и первого рендера истории. Пути сессий,
тела запросов и ключи не выводятся. Это отметки подготовки рендера; фактический
показ кадра и задержки compositor/GPU проверяются отдельно в нативном окне.

`cargo run --release --example gpui_floor` открывает пустое окно того же
GPUI-рендерера без backend и расширений; `-- --assets` подключает общий набор
assets. Это ориентир для разделения затрат renderer/драйвера и состояния
приложения. При сравнении используйте одинаковые display, размер окна и
`Pss_Anon`/`Pss_File`: измерение TUI без терминала исключает его графические затраты.

С флагом `--choose-workspace` клиент вместо workspace показывает выбор
папки: недавние workspace и системный диалог «Открыть папку…». Так его
запускает ярлык из меню приложений. Недавние папки хранятся в настройках
клиента. Относительный путь к файлу профиля (`--config dir/x.toml`)
привязывается к каталогу запуска клиента.

Над вкладками — верхняя полоса (`ui/chrome`), своя, а не из gpui-kit: за
пустое место на ней перетаскивается окно, а нажатие на кнопку или значок
окно не двигает (они делают `prevent_default` на нажатии). Окно рисует
рамку само (client-side decorations), поэтому справа на полосе тихие
значки «свернуть», «развернуть» и «закрыть» — при наведении меняется
только цвет значка (у «закрыть» — красный), фон не подсвечивается. Под niri
окно просит рамку у композитора и этих значков не показывает: niri не
сообщает своё размещение окну со своей рамкой, и gpui-kit рисовал бы вокруг
него отступ с тенью на всё окно, которая на встроенной графике стоит каждому
кадру столько же, сколько остальной интерфейс. Слева логотип: пока агент работает в каком-нибудь чате, его столбцы
бегут волной (при уровне анимаций «меньше» — мерцают). Меню логотипа:
«Настройки», версия и «Выход»; у правого края полосы — значки расширений с
местом «В верхней полосе». Настройки открываются из меню логотипа и
сочетанием клавиш.

Проекты выбираются в боковом меню сессий; отдельного переключателя папки
над полем ввода нет. Новый чат для проекта наследует настройки его последней
сессии. Пустой исходный чат заменяется, чаты других проектов сохраняются.
Другую папку можно открыть через «Открыть папку…» в боковом меню или на
стартовом экране с недавними проектами.

Слева под верхней полосой идёт узкая боковая полоса во всю высоту окна:
сверху кнопки панелей (сессии, затем панели включённых расширений,
например файлы), под ними состояние активного чата (индикатор, слова — в
подсказке) и число других чатов в работе, ниже значки с местом «На
боковой полосе, сверху», у нижнего края — «снизу» (по умолчанию там
контекст, сессия и агент) и в самом низу кнопка настроек. Экран настроек
открывается справа от полосы, кнопка настроек на это время выделена,
повторный клик его закрывает.
Значки встают в столбец, поэтому туда попадают только узкие значки-иконки:
выбор режима и модели, план и значки установленных расширений с текстом
на полосу не перетаскиваются. Высота верхней полосы и ширина боковой растут
вместе с масштабом; сам масштаб меняется в настройках и сочетаниями клавиш.
Поле ввода чата лежит на чуть приподнятом фоне, чтобы не сливаться с
перепиской в светлой и тёмной теме. Над вводом пристыкована общая полоса: проект,
Model/режим и остальные значки расширений, активные вопросы, подтверждения и план.
Подробности выбранного элемента плавно раскрываются над полосой, сохраняя её
положение; ответы сохраняются при переключении между вопросами. Переписка над ним не обрывается, а
плавно уходит в фон. Короткие сообщения (отказ во вложении, ошибка сервера
или профиля) всплывают над полем ввода приглушённой плашкой и сами
исчезают через несколько секунд — дольше для длинного текста — или по
крестику. «+» слева в его нижней строке
прикрепляет изображения; их также можно вставить из буфера (Ctrl+V) или
перетащить файлы в любое место чата. Миниатюры видны над текстом, крестик
при наведении убирает файл. Если в буфере вместе с картинкой есть текст,
вставляется текст. Лимиты host (PNG, JPEG, WebP, GIF; до четырёх файлов,
вместе до 5 МиБ) проверяются сразу, причина отказа всплывает над полем
ввода.
Подтверждения и вопросы агента появляются карточкой прямо над полем ввода.
В подтверждении видны инструмент, причина и команда; Enter при пустом поле
разрешает вызов один раз, Esc отклоняет, а стрелка у кнопки «Разрешить один
раз» предлагает больше не спрашивать про эту команду (или запись в рабочей
папке, если инструмент это допускает). Вопросы идут по одному с переключателем
«N из M»: варианты выбираются кликом или цифрой, свой ответ пишется в строке
карточки, «Пропустить» оставляет вопрос без ответа, крестик закрывает все
вопросы сразу. Текущий план хода тоже висит над полем ввода: свёрнутым он
показывает число готовых шагов и текущий шаг, по клику раскрывается целиком
и исчезает, когда все шаги выполнены.
Инструменты в переписке подписаны своими настоящими именами (`exec_command`,
`apply_patch`, …). Длинная команда или путь в строке плавно гаснут к краю,
а длинный вывод в раскрытой строке показывается первыми строками с
затуханием и кнопкой «Показать всё».
Правки `apply_patch` и документы git используют общий diff: сворачиваемые
карточки файлов, номера строк, `+N −M`, режимы unified/split и копирование
исходного patch. В узком месте split временно становится unified и
восстанавливается при расширении. Длинные строки прокручиваются внутри
своей колонки; большой diff рисует только видимые строки. Если патч не
содержит исходных координат строк, номера остаются пустыми.
Изменённые строки выделяются непрерывной областью и цветной полосой у номеров,
без повторяющихся знаков `+`/`−`. У уведомлений об ошибках рядом с крестиком
есть копирование полного текста с сохранением переносов строк.

Граф git показывает отдельные колонки графа, описания, даты, автора и хеша.
Их ширина меняется перетаскиванием границ, видимость — правым кликом по
заголовку. Выбор строки показывает справа автора, сообщение и дерево
изменённых файлов. Поиск перемещается по коммитам, не ломая дорожки графа.
Файлы и коммиты используют одну временную вкладку: следующий просмотр заменяет
её, двойной клик, Enter или закрепление сохраняет документ.
Во вкладке коммита под шапкой расположен diff на всю ширину; отдельного списка
файлов слева нет. Дерево файлов доступно в боковой карточке графа.
Служебные заголовки `@@ … @@` скрыты, а исходные координаты и копирование patch
сохраняются. Код обеих сторон подсвечивается по языку файла и текущей теме.
Меню и выбор модели используют общую анимацию со стрелкой, текстовые кнопки
имеют одинаковые более свободные отступы. Выделение списков повторяет боковое
меню; ширина колонок графа меняется вдоль всего вертикального разделителя.
Технические имена команд остаются английскими (Push, Pull, Commit, Stage…).

Сообщение может состоять из одних изображений. В переписке отправленные
изображения показываются миниатюрами над сообщением; байты клиент
загружает с сервера (`/image`) при первом показе строки.

## Portable

```bash
python3 scripts/portable.py           # release с архивом
python3 scripts/portable.py --fast    # локальная пересборка
python3 scripts/portable.py --debug   # быстрее всего собрать
python3 scripts/portable.py --fast --reuse-hosts # собрать пакеты, сохранить Core/Desktop
```

`--fast` собирает клиент профилем `fast`: оптимизация как в release, но без
LTO и инкрементально, поэтому правка клиента пересобирается за секунды, а не
минуты; архив не пишется. Агент и backend-пакеты при этом берутся из release.

`scripts/portable.py` и `scripts/test.py` не занимают всю машину: они
перезапускаются в systemd scope примерно с 40% процессоров и памяти, с низким
приоритетом процессора и диска, и ограничивают число задач cargo.
`PROTEUS_BUILD_SHARE=70` меняет долю, `PROTEUS_BUILD_SHARE=100` снимает
ограничение; при заданной `CI` оно не действует.
`--debug` собирает код клиента без оптимизаций: интерфейс может
подтормаживать, для оценки плавности он не подходит.

Скрипт собирает `proteus`, независимые backend-пакеты и клиент, затем
складывает `build/Proteus/` и архив
`build/Proteus-<version>-linux-<arch>.tar.gz`:

- `proteus-native` — запуск: ставит профили из `share/configs` в
  `${PROTEUS_CONFIG_HOME:-~/.config/Proteus-agent}/configs` (именованные
  профили копируются только если их нет, каталоги `fragments`, `prompts` и
  т. п. обновляются), задаёт
  `PROTEUS_BIN` и `PATH` на свои `bin/` и запускает клиент с аргументами;
- `install-shortcut` — ярлык в меню приложений текущего пользователя
  (`~/.local/share/applications/dev.proteus.native.desktop` и значок); ярлык
  использует SVG-иконку проекта и открывает выбор папки. Путь указывает на
  постоянную папку `build/Proteus`: после пересборки ярлык запускает новую
  версию автоматически. После переноса папки запустите его снова,
  `--remove` убирает ярлык;
- `${PROTEUS_CONFIG_HOME:-~/.config/Proteus-agent}/environment` — необязательный
  локальный файл окружения в формате POSIX sh (`export HTTPS_PROXY=…`,
  `export HTTP_PROXY=…`, `export NO_PROXY=localhost,127.0.0.1,::1`). Launcher
  загружает его до запуска клиента: настройки сети общие для приложения,
  сервера и расширений; model-worker получает их через `env_allowlist`
  своего профиля. Ярлык использует тот же launcher, что запуск из терминала;
- launcher при каждом запуске читает ручные системные настройки HTTP/HTTPS proxy
  GNOME/GSettings и передаёт их клиенту, серверу и расширениям через стандартные
  `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY`. Явные proxy-переменные окружения,
  в том числе из файла `environment`, имеют приоритет. Системные исключения
  добавляются в `NO_PROXY`; localhost всегда доступен напрямую. Выключенный
  системный proxy не включается из сохранённых адресов. PAC и отдельный SOCKS
  этим launcher не преобразуются: HTTP-клиенты поставляемой сборки используют
  HTTP proxy;
- `bin/` — клиент, сервер агента и reference-модуль одной сборки;
- `share/extensions/` — самостоятельные процессные пакеты стандартных расширений.
  Поставляемые Rust-бинарники запускаются без Python и исходного checkout; SDK
  используется при разработке пакетов.
- `share/licenses/` — лицензии четырёх репозиториев и Apache LICENSE/NOTICE
  заимствованного кода;
- `share/release-sources.json` — версия, фактические commits всех четырёх
  исходных checkout, их dirty-состояние, платформа и версии инструментов сборки.

## Проверки И Alpha-Релизы

Обычные push в ветку и pull request **не запускают Actions**. В Core, Modules
и Extensions есть только ручной `Manual checks`. В этом репозитории workflow
`Check or release Linux portable` имеет два входа:

- **Run workflow** проверяет закреплённые исходники всех четырёх репозиториев.
  Флаг `build` дополнительно собирает и проверяет релизные архивы, сохраняет
  их как Actions artifact на 14 дней; ручной запуск никогда не публикует релиз;
- **push тега `v<version>` только в Desktop** выполняет те же проверки,
  собирает Linux x86_64 portable и публикует GitHub prerelease. Тег обязан
  точно совпадать с версией в `Cargo.toml`; package-версии Core и reference
  module также должны совпадать. Неправильный тег останавливает сборку.

Workflow использует `ubuntu-24.04`, Rust 1.95.0, Node.js 22.23.4 и Python
3.12.15. Сторонние Actions закреплены полными commit SHA. Кэшируются зависимости
Cargo. `scripts/release.py prepare` загружает именно commits из
`repositories.json`, игнорируя соседние checkout и внешние source overrides;
проверки отклоняют изменённые исходники и несовпадение SHA. Матрица запускает
существующие test runners, в том числе реальные process/sandbox fixtures.
Core gate также собирает самостоятельный Rust SDK starter с собственными
Git pin и lock-файлом и запускает его через conformance tool и реальные
процессные вызовы; зависимость от исходного workspace для сборки starter не нужна.
Перед ними bubblewrap обязан успешно создать namespaces. Только на временном
CI runner снимается мешающий этому AppArmor userns sysctl; runtime-изоляция
процессов продолжает исполняться через bubblewrap без fallback.

После сборки `scripts/release.py smoke` распаковывает архив в другой каталог
и проверяет CLI/Desktop `--version`, launcher, restricted-профиль с fake model,
запись файла, hooks, replay, HTTP-аутентификацию и упакованные
расширения. Используются отдельный HOME и синтетические сессии, без ключей модели.
Для JS hooks smoke отдельно перемещает поставляемые assets в путь с пробелом,
проверяет launchers, инспекцию без исполнения команд и bundled Node gate.
Локально эта часть запускается через
`python3 scripts/test_portable_hooks.py build/Proteus` без пересборки исходников.
Это headless-проверка; запуск окна и работу с живой моделью проверяют отдельно.

Нативный стенд ползунка открывает синтетическую историю из 5 000 сообщений,
проверяет подгрузку, вытеснение страниц и переходы по всему диапазону:

```bash
cargo run --locked --profile fast --example history_scrollbar -- \
  --verify build/verification/history-scrollbar-native.json
```

Он использует стандартный scrollbar GPUI и тот же адаптер диапазона, что чат.
Проверки состояния истории и устаревших ответов входят в `scripts/test.py`.

В `build/release/` и GitHub prerelease попадают versioned portable, архив
точных tracked-исходников четырёх репозиториев, `release-sources.json`,
`release-smoke.json`, `LICENSES.txt` и `SHA256SUMS`. Smoke-отчёт привязан к SHA256
проверенного архива. Публикация сначала загружает файлы в draft и только затем
открывает prerelease; сбой загрузки оставляет draft для повторного запуска.
Уже опубликованный релиз workflow не перезаписывает.

Первая платформа поставки — Linux x86_64 с glibc 2.39+ и системными библиотеками
GPUI. Node.js, Python, git, ripgrep и bubblewrap устанавливаются отдельно.
Для разработки остаётся обычный `python3 scripts/portable.py --fast`; он не
запускает Actions и не публикует релиз.

## Расширения без пересборки

Расширение — папка `~/.config/dev.proteus.native/extensions/<id>/` с
`extension.json` и любой программой. Клиент читает такие папки при первом
обращении к каталогу и рисует присланные программой виджеты сам. Расширение
можно установить ZIP-архивом в «Клиент → Расширения» (кнопка или
перетаскивание архива на страницу): архив до 64 МиБ, до 128 МиБ и 4096
файлов в распакованном виде, `extension.json` в корне, без ссылок и путей
за пределы папки; права на исполнение файлов сохраняются. Установка и
удаление применяются сразу, без перезапуска (`declarative/package.rs`).
Ошибки манифестов видны там же, в блоке «Новое расширение».

Те же расширения можно устанавливать из git-каталогов на странице
«Каталог» (первый пункт настроек). Сверху поиск, фильтры «Обзор / Все /
Установленные / Обновления» и тип записи. Страница открывается обзором, а
не всем списком: обновления и установленные записи (по пять, с «Показать
все»), карточки типов и источников с числом записей, у источника с
несколькими категориями — кнопки категорий. Карточка сужает список до типа,
источника или категории (сужение видно кнопкой с крестиком в строке типов);
полный список появляется также при поиске или фильтре «Все», а Esc шаг за
шагом возвращает к обзору. Список однострочный: значок
типа, название, версия, источник и кнопка установки или обновления. Клик по
записи открывает справа описание, README и «Удалить» (в узком окне панель
занимает всю ширину), Esc закрывает эту
панель. С клавиатуры: стрелки, PageUp/PageDown, Home/End ходят по списку и
сразу открывают запись, Enter устанавливает или обновляет её, `/` и Ctrl+F
переводят в поиск, а Enter или ↓ в поиске возвращают к списку. Источники
скачиваются параллельно, каждый список появляется по готовности; зависший
git останавливается по таймауту вместе со своими дочерними процессами.
Git-репозитории и ветки добавляются, обновляются и убираются в окне
«Источники»; там же одной кнопкой добавляются открытые каталоги skills
(Anthropic, OpenAI, Superpowers, Hugging Face), а пустая страница предлагает
подключить их все сразу. Репозиторий без `proteus-catalog.json` читается как
репозиторий Agent Skills: каждая папка с `SKILL.md` — отдельный skill, в
панели записи вместо README показываются его инструкции. Поддержаны также
Agent Plugins, отдельные skills и готовые
MCP-конфигурации; пакет и MCP-сервер сразу записываются в профиль, без
черновика и «Сохранить», пока в настройках нет других несохранённых правок.
Нужен системный `git`, без новых сетевых сервисов; установка работает
локально, не собирает программы и не скачивает их зависимости. [Формат и
готовый пример каталога](examples/catalog/README.md).

Все поставляемые расширения используют тот же публичный процессный
механизм. Их исходники и упаковщик находятся в [Proteus-desktop-extensions](https://github.com/Proteus-harness/Proteus-desktop-extensions),
автор — `Proteus Project`. Включены по умолчанию. Исходники находятся в отдельном репозитории и поставляются по закреплённой ревизии.

Portable читает пакеты из `share/extensions`; сборка из `target` — из
`../Proteus-desktop-extensions/packages` при общей раскладке. Переменная `PROTEUS_EXTENSIONS_DIR` заменяет
источник поставляемого набора. Пользовательская папка с тем же id перекрывает
поставляемую, включая ошибочный пакет: ошибка показывается явно.
ZIP с существующим id атомарно обновляет пользовательский пакет; настройки
порядка, включения и значков сохраняются. При удалении пользовательской версии
поставляемая восстанавливается выключенной. Перезапуск клиента не нужен.

[Протокол v3, поверхности и виджеты](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/main/PROTOCOL.md).
Программа получает HTTP-доступ к app-server, а при `session_events: true` —
снимок состояния активного чата и изменения метаданных ленты без текста ответа.
Квоты, аналитика и файлы запрашиваются через HTTP самим процессом. Общие
нативные виджеты включают дерево, граф, редактор и терминал. Новый вид виджета
требует обновления клиента; логика и интерфейсы на существующих виджетах
меняются установкой пакета. Версия протокола 1 отвергается явно.

Повторная отрисовка одной версии дерева использует уже подготовленные поля
и строки списков. SVG заново подготавливаются при новой версии дерева или
смене масштаба окна и интерфейса; локальный ввод и раскрытие сохраняют состояние.

Пример: `examples/extensions/sessions-overview` (достаточно symlink в папку
расширений). Если процесс упал, поверхность показывает stderr и кнопку
перезапуска. Строка не в UTF-8 считается плохим сообщением и не обрывает
чтение. При закрытии клиент останавливает всю группу процессов программы:
`SIGTERM`, через секунду `SIGKILL`.

Устройство:

- `transcript` — headless модель ленты: snapshot и live fold runtime
  событий по правилам `app_server/turn_progress.rs`, без GPUI;
- `tool_display` — заголовки инструментов, разбор patch и плана;
- `settings` — headless черновик и каталог страниц настроек агента поверх
  `/config/builder`, `/addons` и `/config/history`. Отдельный первый пункт —
  Каталог (git-источники дополнений). Блок «Агент» — страница
  на каждый слот (Model, Workflow, Context вместе с context providers, Tools,
  Policy, Hooks; неизвестные слоты добавляются по порядку; сжатие истории и
  отбор инструментов — обработчики на странице Hooks). Блок «Подключения» —
  Modules (процессные components), MCP (добавление, правка и удаление
  серверов профиля, серверы пакетов только переключаются), Skills, Packages
  (Agent Plugins: добавление папки, импорт ZIP и удаление пакета) и
  History с откатом; поля строятся по `config_schema` модулей (вложенные
  `object` — раскрывающимися группами, у каждой формы есть режим JSON и кнопка
  открытия файла профиля; описания полей, инструментов, модулей, обработчиков
  и skills — во всплывающей подсказке у названия, строки списков однострочные,
  длинные названия затемняются к концу, поле сразу показывает
  действующее значение, а сброс появляется только у своего значения,
  отличного от default), сохранение отправляет только изменённые разделы.
  Поиск над списком страниц (`Ctrl+F` в настройках) находит страницы,
  параметры модулей, реализации слотов, инструменты, модули, обработчики,
  skills, MCP-серверы, пакеты и настройки клиента; переход раскрывает нужные
  группы, прокручивает к строке и кратко подсвечивает её;
- `catalog` — частичный git-кэш (скачиваются дерево и файлы списка, файлы
  записи — при открытии и установке), индекс `proteus-catalog.json` или папки Agent Skills
  без индекса, список открытых каталогов, установка по типу
  записи и привязка к профилю; `packages` — общие
  проверка файлов и публикация папок для git-каталогов и ZIP. Старые версии
  Agent Plugins не перезаписываются;
- `preferences` — настройки самого клиента (тема и палитры, масштаб, скругление углов, анимации,
  подсказки к кнопкам, размер текста и ширина диалога, компактные цепочки инструментов, автопрокрутка,
  отправка сообщения, уведомления, включённые
  расширения, места и закрепление значков, раскладка вкладок, git-источники
  каталогов и сведения об установках) в
  `~/.config/dev.proteus.native/preferences.json`. Файл пишется целиком через
  временный рядом; файл, который не удалось прочитать, переименовывается в
  `preferences.json.broken-<время>`, а клиент стартует с настройками по
  умолчанию. Масштаб меняет размер
  шрифта темы, от которого считаются все rem-размеры окна (Ctrl + =,
  Ctrl + −, Ctrl + 0), и радиусы скруглений; фиксированные размеры задаются
  через `prefs::scaled`, а раскладка вкладок хранится в единицах при 100%.
  Компактные кнопки, поля и строки используют `theme.radius` (8 при 100%).
  Радиус крупных поверхностей `theme.radius_lg` настраивается во «Внешнем
  виде → Скругление углов»: 0–32 px, по умолчанию 16 px. Поле сообщения,
  виджеты, меню и карточки настроек меняются сразу, вместе с масштабом;
  мелкие метки берут половину `theme.radius`.
  Длинные однострочные надписи (вкладки, сессии, файлы, строки
  инструментов, пункты меню) не обрываются многоточием, а затухают у
  правого края: `ui/fade.rs` снижает прозрачность последних видимых букв,
  поэтому затухание не зависит от фона под надписью.
  Палитры — темы `gpui-kit` из реестра (`ui/theme`): встроенные «Графит»
  (тёмная по умолчанию), «Сланец» (холодная тёмная, с более различимыми
  фоном, блоками и границами), «Светлая» (`ui/theme/proteus.json`), «Чёрная» и
  «Белая», плюс файлы `~/.config/dev.proteus.native/themes/*.json` в
  формате тем `gpui-kit`, прочитанные при запуске (ошибки видны в
  «Клиент → Внешний вид»). Тёмная и светлая палитры выбираются отдельно
  (`themes.dark`/`themes.light`), «Тема» решает, какая из них показана;
- `tabs` — headless раскладка вкладок: дерево областей (`tree.rs`:
  область или разделение по строке/столбцу, нормализация и проверка
  формы), область со своими вкладками и закреплёнными впереди
  (`pane.rs`), размер ребёнка разделения — доля или фиксированные пиксели
  (`size.rs`), раскладка целиком, исходная раскладка и проверка
  сохранённой формы (`layout.rs`), открытие вкладок и выбор области для
  них (`open.rs`), перенос, разделение и закрытие (`ops.rs`),
  закрепление и закрытие остальных/справа (`pins.rs`), геометрия областей
  в пикселях, соседи по направлению и изменение размеров (`geometry.rs`);
  вкладки чатов `chat:<папка сессии>` и документов
  `<расширение>:<аргумент>`, вкладка предпросмотра, выбор активного чата;
- `sessions` — имена, закрепление и архив сессий (настройки клиента) и
  порядок списка;
- `attention` и `notify` — какие смены активности сессий важны (закончил,
  ждёт подтверждения, ждёт ответа; первое увиденное состояние — точка
  отсчёта) и системное уведомление через `notify-send`. Уведомление
  показывается, только когда окно в фоне; кнопка «Открыть» возвращает к
  этому чату. Без `notify-send` уведомлений просто нет;
- `terminal` — общий headless эмулятор на `alacritty_terminal`: PTY,
  цветные строки, xterm-клавиши и bracketed paste. Доступен процессам
  через виджет `terminal`;
- `Proteus-desktop-extensions/packages` — логика файлов, аналитики и остальных
  поставляемых расширений; `ui/extensions/declarative` — общий рендерер
  протокола и жизненный цикл процессов. Аналитика выбирает сохранённую
  сессию без переключения чата; архитектура относится к активному чату.
  Оценка стоимости использует сохранённую в пакете таблицу тарифов;
- `api`, `connection` — блокирующие HTTP-запросы и SSE-поток в отдельных
  потоках;
- `ui` — окно: вкладки (чаты и документы) в дереве областей (`ui/tabs`:
  рендер дерева, полоса вкладок и вкладка, контекстное меню и меню «+»,
  разделители, зоны сброса вкладки), боковая панель (`ui/panels`: список
  сессий, панели расширений и сама панель у полосы), экран настроек (блоки «Агент»,
  «Клиент» и «Расширения»); `ui/chat` — самостоятельный вид одной сессии
  (`Chat`): поток событий, лента, подтверждения, вопросы, очередь и поле
  ввода; лента — свой виртуальный список (`ui/chat/scroller.rs`), который
  плавно догоняет конец ответа, перестаёт следовать при прокрутке вверх и
  возвращается к нему внизу (или по кнопке «К последним сообщениям»);
  загруженная сессия открывается сразу на конце, а длинные ответы
  разбираются при загрузке, чтобы строка не меняла высоту при прокрутке к ней;
  `ui/chats.rs` — открытые чаты окна, активный чат и список
  сессий; `ui/motion/` — единая система анимаций: три длительности
  (120/180/260 мс), сглаживание входа и выхода, появление, поочерёдное
  появление строк списка, раскрытие по высоте и ширине, плавные числа;
  пружины — только для раскрытия. Раскрытый блок помнит свою высоту, поэтому
  сворачивание начинается без пустого кадра; страница настроек не укорачивается
  под видимой областью при сворачивании, пока её не прокрутят вверх
  (`ui/floor.rs`); «Обновить» и сохранение перечитывают профиль, не убирая
  страницу, так что прокрутка и раскрытые блоки остаются. `ui/tabs/motion.rs` — появление и
  исчезновение вкладок и перестановка областей при разделении и закрытии
  (во время перетаскивания границы и изменения окна области не плывут).
  Сессии и дерево файлов при первой загрузке или раскрытии папки
  появляются поочерёдно, карточки подтверждений и заметки над полем ввода —
  один раз, без повтора при возврате на вкладку; индикаторы загрузки файла,
  профиля и истории показываются, только если она длится дольше 200 мс. Уровень
  анимаций из настроек учитывается везде, ответ модели при стриминге
  проявляется по словам. Шаги колеса мыши (строками) окно перехватывает
  и раздаёт короткими пиксельными шагами за несколько кадров
  (`ui/wheel.rs`), так что любая прокрутка плавная. Тачпад прокручивает
  как есть, а после быстрого жеста на Linux лента продолжает катиться и
  плавно тормозит (`ui/wheel/fling.rs`): gpui не передаёт момент, когда
  пальцы подняты, поэтому концом жеста считается пауза в событиях. Скорость
  берётся по последним ~20 мс жеста, так что пальцы, затормозившие перед
  отрывом, не запускают скольжение; новая
  прокрутка или клик останавливают инерцию. При выключенных анимациях
  колесо и тачпад идут как есть. С зажатым `Ctrl` любая
  прокрутка (колесо и тачпад) идёт в 5 раз быстрее,
  `ui/drag.rs` — общий вид перетаскивания.
  Каждый чат — кэшированное представление: волна логотипа и индикаторы
  загрузки не перерисовывают переписку. Индикаторы и логотип идут от общего
  таймера `ui/motion/ticker.rs` (24 кадра/с, 8 — когда окно не в фокусе).
  Крутится только инструмент в работе (`running`, `approved`); прерванный
  или неизвестный показывает значок остановки. Разметка ответов хранится
  весь срок жизни чата, так что прокрутка назад и смена вкладок не
  разбирают её заново.

Список сессий и дерево файлов — панели, а не вкладки: одна из них
показывается в боковой панели между полосой и вкладками (при первом
запуске — сессии). Кнопка панели на полосе показывает её, повторный клик
по кнопке показанной панели закрывает боковую панель; `Ctrl+Shift+H` и
`Ctrl+Shift+E` открывают сессии и первую панель расширения и переводят на
неё клавиатуру, а с неё возвращают к активному чату. Ширину боковой
панели меняет перетаскивание её правого края (от 180 до 640 пикселей,
сохраняется при отпускании), двойной клик по краю возвращает 264 пикселя.
Показанная панель и ширина хранятся в `sidebar` в `preferences.json`.
Боковая панель выезжает и уезжает по ширине, не перестраивая содержимое,
а сменившая другую панель проявляется. Каждая панель начинается общей
шапкой: заголовок, действия панели (у сессий — «Новая сессия») и кнопка
«Скрыть панель».

Список сессий раскладывает незакреплённые сессии по папкам проектов:
проекты идут от недавнего к давнему, клик по заголовку сворачивает папку,
«✎» при наведении открывает в проекте новый чат. В папке видно пять
последних чатов (и выбранный), остальные — по «Показать больше».
Лупа в заголовке сессий раскрывает поиск в той же строке; `Ctrl+F` в панели
делает то же. Поле оставляет сессии, в имени или первом сообщении
которых есть запрос без учёта регистра; при поиске подходящие архивные
сессии показываются под заголовком «Архив». Enter в поле поиска переводит
клавиатуру в список. В списке `↑`/`↓`, `Home`/`End` двигают курсор,
Enter открывает сессию под ним и переводит клавиатуру в чат, `F2`
переименовывает, `Ctrl+F` возвращает в поиск. Esc в панели очищает поиск,
а при пустом поле сворачивает его и возвращает клавиатуру списку;
Esc из списка возвращает её в чат.

Чатов может быть открыто несколько, каждый — отдельная вкладка со своим
потоком событий; закрытие вкладки останавливает поток. Клик по сессии в
списке показывает её чат во вкладке предпросмотра (или переключает на уже
открытую), двойной клик или отправка сообщения оставляют вкладку; новая
сессия открывается обычной вкладкой. Закрыть можно любую вкладку; когда
чатов и документов не осталось, остаётся пустая область с кнопкой
«Новая сессия». Раскладка
вместе с чатами восстанавливается при запуске, вкладки удалённых сессий
закрываются. Активный чат — показанный в области с фокусом, иначе
последний такой; к нему относятся заголовок окна, выделение в списке,
настройки агента, значки расширений и `Host`.

Меню сессии в списке (правый клик или «⋯» при наведении): переименовать
(имя правится прямо в строке, Enter или уход фокуса сохраняет, Escape
отменяет), закрепить сверху, убрать в архив или вернуть, удалить чат.
Имена, закрепление и архив — настройки клиента (`sessions` в
`preferences.json`, headless-модуль `sessions.rs`); своё имя видно и во
вкладке, и в заголовке окна. Архивные сессии скрыты под переключателем
«Архив · N» в конце списка. Удаление подтверждается диалогом, закрывает
вкладку чата и вызывает `POST /delete-session`.

Расширения клиента (`ui/extensions`) описываются `Manifest` и получают
доступ к окну через публичный протокол процессов; внутри клиента его
адаптер `Host` читает активную сессию и вкладку, передаёт API, события
смены сессии, завершения хода и навигации, открывает документы.
Расширение может дать значок (под полем ввода — слева или справа рядом с
отправкой, в верхней полосе — у левого или правого края, на боковой
полосе — сверху или снизу),
панель, страницу настроек и вкладки документов. Поставляемые пакеты: режим разрешений и модель вместе с
глубиной рассуждений активного чата (по умолчанию под полем ввода). Клик по
ним открывает выбор над или под значком: выбранный вариант выделен цветом,
на значке модель без провайдера (он в заголовке списка моделей). Режимы,
модели и уровни рассуждений названы так, как их называет сервер (`normal`,
`gpt-5.6-luna`, `high`), без перевода. В выборе модели сверху текущая
модель — клик открывает список моделей в том же окне, после выбора оно
возвращается назад; под ней уровень рассуждений и его шкала. Рассуждения задаются
ступенчатой шкалой постоянной ширины — засечка на каждый уровень, клик или
протягивание, применяется при отпускании; кнопка сброса возвращает уровень
профиля. С клавиатуры значок открывается Enter или пробелом, `↑`/`↓` и Tab
ходят по строкам выбора по кругу, Enter выбирает, `←`/`→` в выборе модели
сдвигают рассуждения на уровень. Esc в списке моделей возвращает назад, иначе
закрывает выбор и возвращает клавиатуру туда, где она была. Перетаскивание значка по-прежнему
переносит его. Далее контекст (кольцо
заполнения), план, лимиты модели (`/model/quota`), сессия, агент и файлы:
значок с числом изменений, панель с деревом и списком изменений git, файлы
во вкладках с просмотром и diff против HEAD. Одиночный клик открывает файл во
вкладке предпросмотра (курсив), которую заменит следующий файл; двойной
клик, `Enter` или перенос вкладки оставляют её. Дерево следует за активной
вкладкой области с фокусом. Подробности значков — во
всплывающей подсказке; подсказки клиента привязаны к элементу под курсором, а
не к самому курсору (`ui/tip.rs`, общий слой подсказок gpui-kit). Кнопки и
переключатели клиента собираются через `ui/kit.rs`: рамка фокуса gpui-kit
видна, только пока окном управляют с клавиатуры, так что фокус после клика
или выставленный самим клиентом её не показывает. Кликабельные строки и
карточки (варианты, раскрывающиеся формы, строки аналитики, инструменты в
чате, значки, выбор в окнах) помечены там же `Pressable`: Tab доходит до них,
Enter или пробел нажимает, фокус подсвечивается как наведение. Подсказки к
кнопкам (`Hint` там же) короткие и по настройке «Подсказки к кнопкам»
показывают описание с сочетанием клавиш, что-то одно или ничего; сочетание
берётся из текущих настроек клавиш. Сведения значков, полные названия вкладок
и пути видны всегда.

Список расширений — «Клиент → Расширения»: удержание строки начинает
перетаскивание, как в Hooks и sortable-списках расширений. При фокусе строки
Ctrl+Shift+↑/↓ меняет порядок с клавиатуры. Переключатель включает расширение, установленные из архива
удаляются вместе с папкой (после подтверждения), «Восстановить стандартный
список» сбрасывает порядок, включение и места значков, не трогая
установленные. Каждое включённое расширение получает страницу в блоке
настроек «Расширения» в том же порядке: переключатель у заголовка, что оно
добавляет, место и закрепление значка, источник; у аналитики («Расход и
контекст», «Анализ ходов», «Архитектура») страница — сам отчёт. Порядок
хранится в `extensions.order`. Значки
перетаскиваются между полосами (у каждой панели их две — у левого и у
правого края) и внутри них живой перестановкой: значок сам встаёт в полосу
под курсором туда, где окажется после отпускания (перед значком, середина
которого правее курсора, или в конце), соседи плавно расступаются, а он
проявляется по мере того, как открывается место; его
прежнее место смыкается; вдали от всех полос он возвращается на своё место.
Отпускание только фиксирует показанное. Пока значок тянется, все полосы,
куда его можно бросить, обведены, а та, где он стоит, подсвечена ярче;
курсор ловится с запасом вокруг полосы (20 пикселей по бокам, 14 сверху и
снизу), пустая полоса раскрывается ровно на одно место
(`ui/badges/arrange.rs`, `motion::Slide`). Правый клик только скрывает значок или
закрепляет его на месте; у закреплённого значка пункта «Скрыть» нет.
Скрытый значок возвращается в настройках
расширений. Значки под полем ввода, включая выбор модели, видны только у
активного чата.

Окно делится на области произвольно, по горизонтали и по вертикали; у
каждой области своя полоса вкладок с кнопкой «+» (новая сессия, терминал;
новая вкладка открывается именно в этой области).
Правый клик по «+» — действия с областью: «Закрыть область» (её
вкладки переходят в предыдущую область, у первой — в следующую) и
«Закрепить размер» (`crates/tabs/src/lock.rs`): закреплённая
область хранит текущий размер в пикселях вдоль своего разделения и не
меняет его при изменении окна и закрытии соседей, разделителем её
по-прежнему можно подвинуть. Меню закреплённой области предлагает только
«Открепить размер». Её больше ничего не делит: края при
перетаскивании вкладки принимают её внутрь, пункты разделения и `Ctrl+\`
не действуют, новый документ не открывается рядом разделением. Снятие
закрепления возвращает ей долю от текущего размера. Если рядом не осталось
области, которая заберёт остальное место, его забирают соседи:
фиксированная переходит на долю, а закреплённый сосед теряет закрепление. Пункт
недоступен у единственной и у пустой области; оставшись одна,
область теряет закрепление (поле `locked` области в `tabs`). Когда соседняя
область пустеет (её последняя вкладка закрыта или перенесена), а рядом
остались только закреплённые и фиксированные, на её месте остаётся пустая
область: закреплённая не растёт. Новая вкладка открывается в пустой области;
«Закрыть область» у неё отдаёт место ближайшему соседу (сначала
незакреплённому), снятие закрепления у соседа тоже её убирает.
Закреплённые вкладки стоят в начале полосы,
показываются компактно и без кнопки закрытия;
перенос сохраняет закрепление. Когда вкладкам тесно, первыми сужаются
самые широкие, короткие остаются целыми дольше; сузившись до предела, полоса
прокручивается. Правый клик по вкладке — меню
«Закрепить/Открепить», «Закрыть», «Закрыть другие», «Закрыть справа»
(закреплённые не закрываются), «Разделить вправо/вниз»; средний клик
закрывает незакреплённую вкладку. Вкладка, перетащенная в середину области, переходит в неё, к
краю — отделяется в новую область с этой стороны; подсвечивается
занимаемая часть. Пустая область закрывается (кроме единственной для чатов
и держащей место закреплённого соседа),
разделение с одной областью схлопывается, отделить единственную вкладку
области нельзя. Между областями — линия в пиксель; тянуть её можно за
полосу в несколько пикселей вокруг. Размеры меняются разделителями (минимум 240×160 пикселей
на область) и сохраняются при отпускании. Двойной клик по разделителю
делит место поровну между незакреплёнными областями. Документ не перекрывает
показанный чат: он открывается в другой области, а при одной широкой
области — справа от неё; новый чат присоединяется к показанному.
Следующий файл предпросмотра встаёт на место прежнего без анимации
вкладки.
При перетаскивании под курсором едет копия элемента, а сама вкладка
встаёт в полосу, над которой курсор, туда, куда ляжет: соседние вкладки
расступаются, её прежнее место закрывается, закреплённая остаётся среди
закреплённых. Над содержимым области или вдали от полос вкладка
возвращается на своё место; отпускание лишь фиксирует перестановку.

Клавиши: `Ctrl+,` — настройки, `Ctrl+Shift+E` — панель файлов,
`Ctrl+Shift+H` — панель сессий (повторное нажатие с панели возвращает к
чату), `Ctrl+N` — новая сессия, `Ctrl+Tab`/`Ctrl+Shift+Tab` —
вкладки активной области, `Ctrl+\` / `Ctrl+Shift+\` — отделить активную
вкладку вправо / вниз, `Ctrl+Alt+стрелки` — соседняя область,
`` Ctrl+` `` — новый терминал (он же в меню «+»),
`Alt+←`/`Alt+→` и боковые кнопки мыши — назад/вперёд по истории вкладок и
страниц настроек. Эти сочетания меняются в списке команд.
`Alt+↑`/`Alt+↓` — соседняя страница настроек, `Ctrl+F` в настройках — поиск
по ним, `Ctrl+S` — сохранить профиль. Настройки открываются с клавиатурой на
списке страниц: `↑`/`↓`, `Home`/`End` выбирают страницу, Enter или `→`
переходят к первому элементу страницы. На странице `↓`/`↑` (и Tab/Shift+Tab)
ходят по её полям, переключателям и кнопкам, включая строку сохранения, а
страница прокручивается к выбранной строке; `↑` с первого элемента и `←`
возвращают в список страниц. Многострочные поля оставляют стрелки для своих
строк, из них выводят Tab или Esc. `↓` в поиске
ведёт в список страниц или в найденное, по которому ходят `↑`/`↓`. Esc в
настройках по очереди отменяет ожидающее подтверждение удаления, очищает
поиск, сворачивает раскрытые формы, возвращает клавиатуру со страницы в
список страниц и затем возвращает к чату; с несохранёнными изменениями экран
не закрывается, а напоминает сохранить или сбросить их. Сочетания команд окна
меняются в «Настройки → Сочетания клавиш» (headless-модуль `shortcuts.rs`,
переопределения в `preferences.json`; keymap пересобирается из них в
`ui/keys.rs` без перезапуска).
Во вкладке терминала клавиши идут оболочке раньше привязок приложения
(`Ctrl+N`, `Tab`, `Ctrl+C`); приложению остаются команды окна, кроме
«Новая сессия», и `Ctrl+Shift+…` (кроме `Ctrl+Shift+V` — вставка). Прокрутка колесом листает историю; выделения
мышью и мышиного режима приложений пока нет. В дереве файлов: стрелки, `Home`/`End`, `PageUp`/`PageDown`, `Enter` — открыть файл во вкладке,
`Space` — предпросмотр или свернуть папку, `/` или `Ctrl+F` — поиск по проекту.
Esc очищает поиск, при пустом — возвращает клавиатуру в чат.

## Лицензия

Как в [Zed](https://github.com/zed-industries/zed), лицензия задана у каждого
крейта: поле `license` в Cargo.toml и ссылка на `LICENSE-GPL` или
`LICENSE-APACHE` в корне. Приложение — GPL-3.0-or-later, потому что содержит
код, заимствованный из Zed; `crates/diff` и `crates/tabs` также используют
GPL-3.0-or-later, `crates/client-common` — Apache-2.0.
Proteus-core и Proteus-modules остаются под MIT — это отдельные программы,
клиент общается с ними по HTTP. `python3 scripts/check_licenses.py` проверяет
разметку.

### Общие примитивы UI

Расширение поставляется отдельной программой с `extension.json` и строит UI
через публичную схему: изменение или установка пакета не пересобирает клиент.
Для выбора Model/Branch используется общий `picker` с поиском и клавиатурой,
для порядка произвольных строк — `sortable` с удержанием, drag и анимацией
соседей. `loading`, `empty`, `disclosure`, `tree`, `list`, `lanes`, `diff`
предоставляют готовые состояния и поведение. Нативные примитивы одинаковы у
встроенных страниц и сторонних процессов; отдельной логики по имени пакета нет.
Схема, required features, SDK и примеры — в `../Extensions/PROTOCOL.md`
соседнего репозитория. Внешний пакет объявляет используемые capabilities и
передаёт данные/actions; анимации, clip-aware подсказки, фокус и ввод обрабатывает
клиент. При закрытии и восстановлении вкладки тип документа не меняет поведение.
